**Backlog:** Documents · P0 · deps FP-009, FP-026 · acceptance: *Expected_version; immutable posted version; source/correction graph; duplicate post conflict*

## Было

- **Торговые документы** (`documents`): версии нет; ожидаемое состояние — по `updatedAt` и необязательно (последний
  записавший побеждает); истории нет; основание — `attributes.baseId` без проверки (можно было указать документ
  другой организации).
- **Бухгалтерские документы** (`acc_documents`): версия и неизменяемая история были; ожидаемая версия — только при
  изменении (при проведении/отмене — нет).
- **Повторное проведение** уже проведённого документа (обоих видов) молча возвращало успех: второй пользователь,
  нажавший «Провести», не узнавал, что документ уже проведён другим (и какой версией).
- **Проведённое содержимое можно было изменить «на месте»** любым писателем БД (старый модуль, обмен, SQL) — без

- Связи документов — только внутри бухгалтерии (основание, сторно); граф через торговлю и ЭСФ не строился.

## Стало

- **Ожидаемая версия.** Торговые документы получили `version` (растёт при каждом изменении содержимого) и
  `posted_version` (какая версия проведена). Изменение — только с `expectedVersion` (без неё — 428
  `VERSION_REQUIRED`, устаревшая — 409 `VERSION_CONFLICT` с текущей версией); проведение, снятие проведения,
  пометка на удаление, сторно — с необязательной `expectedVersion` (если передана — проверяется). Веб передаёт её
  во всех действиях. Старый `expectedUpdatedAt` по-прежнему принимается.
- **Неизменяемая проведённая версия.**
  - История версий торговых документов `document_versions` (действие, снимок шапки и строк, sha256 содержимого,
    кто, причина), как у бухгалтерских (им добавлен хэш). Обе истории неизменяемы (триггеры БД).
  - Изменение проведённого документа — только новой версией с причиной: сервис снимает проведение, меняет и
    проводит новую версию в одной транзакции; прежняя проведённая версия остаётся в истории как была.
  - **Защита на уровне БД:** изменить шапку проведённого документа без увеличения версии, вставить/изменить/удалить
    его строки — нельзя (ошибка `DOC_POSTED_IMMUTABLE`), кто бы ни писал. Служебные поля (статус обмена) — можно;
    удаление документа целиком (каскад строк) — можно; документ, создаваемый сразу проведённым в той же транзакции
    (касса, старые модули), — собирается как раньше.
- **Конфликт повторного проведения.** Строка документа блокируется (`FOR UPDATE`), параллельные проведения идут по
  очереди; второе получает 409 `DOC_ALREADY_POSTED` с проведённой версией. Законный повтор того же запроса (обрыв
  связи) — через `Idempotency-Key`: возвращается ответ первого, не конфликт.
- **Граф документов** `document_links` (BASED_ON — на основании, REVERSAL_OF — сторно, ESF_FOR — ЭСФ по документу,
  CORRECTION_OF — исправленный/дополнительный ЭСФ) ведётся триггерами БД по ссылкам самих документов и переносится
  для существующих; связь записывается только между документами одной организации. Основание торгового документа
  проверяется (своя организация). `GET accounting/document-graph/:type/:id?depth=` — обход в обе стороны (по
  умолчанию глубина 5, до 200 узлов) с краткими карточками (номер, дата, статус, сумма, версия, проведённая версия).
  `GET accounting/trade-documents/:id/versions` — история версий.
- Импорт банковской выписки не проводит повторно уже проведённый документ.

## Проверка

- Интеграционные `documents-versions.int-spec.ts` (5): версия обязательна/устаревшая, история с хэшем; параллельные
  проведения (1 успех, 4 × 409, склад и проводки один раз), повтор 409 с версией, конфликт версии при проведении;
  проведённое неизменяемо (БД: шапка, строки — изменение/удаление/вставка; служебное поле — можно), правка новой
  версией с причиной, хэши (проведение не меняет содержимое), неизменяемость истории, снятие проведения; бухгалтерские
  документы — проведённая версия, правка на месте запрещена БД, перепроведение новой версией, хэши, конфликт версии;
  граф заказ → отгрузка → ЭСФ → исправленный ЭСФ в обе стороны и с глубиной, сторно, основание другой организации —
  отказ сервиса и отсутствие связи при прямой записи, чужой корень — 404.
- HTTP под рабочей ролью `documents-http.int-spec.ts`: повторное проведение 409, повтор с тем же `Idempotency-Key` —
  прежний ответ; изменение без версии 428; версии и граф другого клиента — 404; **RLS прямым запросом** — история
  версий другого клиента не видна.
- Существующие тесты переведены на новый контракт: «повторное проведение не создаёт дублей» → «параллельные
  проведения: один успех, остальные 409, одна активная запись»; правка документа «в обмене» — новой версией
  (правка на месте отклоняется БД); изменение торгового документа — с `expectedVersion`.
- **Мутации — 22/22 пойманы** (версия не обязательна и устаревшая принимается — оба вида документов, повторное проведение «тихим успехом» — оба вида, проведённая версия не запоминается, правка проведённого без новой версии, история не пишется, хэш со статусом, основание другой организации, снятие проведения без проверки версии, граф без фильтра организации, в одну сторону, без глубины, чужой корень, БД: шапка и строки проведённого, бухгалтерский документ на месте, связь с другой организацией, изменяемая история, версии без проверки организации по HTTP).
