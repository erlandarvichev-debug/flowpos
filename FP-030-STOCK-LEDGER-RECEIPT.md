## Стало

### Журнал складских движений (`stock_movements`)

- Каждое изменение остатка — строка журнала: товар, склад (ячейка), **количество со знаком**, **стоимость** (если
  известна при движении) и её основание, вид движения, **источник** (тип, документ, строка, версия документа),
  причина, кто и когда.
- **Остаток меняется только журналом** — триггер на вставку движения прибавляет количество к строке `stock`. Прямая
  запись количества в `stock` (вставка с ненулём, изменение, удаление ненулевой строки) — ошибка БД
  `STOCK_LEDGER_ONLY` для любой роли, включая владельца БД. Резерв (`reserved`) меняется как раньше.
- **Движения неизменяемы** (`ACC_IMMUTABLE`). Отмена проведения, пометка на удаление, изменение проведённого документа
  — **встречные движения** (`reversesId`, одно на исходное — уникальность в БД; встречное обязано точно совпадать с
  исходным по товару, складу, ячейке, организации и количеству с обратным знаком).
- Первичное заполнение: текущий остаток записан одним движением `OPENING` (источник `BACKFILL`) — сумма журнала
  совпадает с остатком с первого дня. Документ, проведённый до журнала, при снятии отменяется обратными движениями
  (`PRE_LEDGER`) — они встречные к начальному остатку и повторно не отменяются.
- Обслуживание (удаление данных клиента целиком) — только ролью миграций (BYPASSRLS) с
  `SET LOCAL flowpos.stock_maintenance = 'on'`; рабочая роль приложения так не может даже с этим флагом.
- Все писатели остатка переведены на журнал: бухгалтерские торговые документы, старые модули (приёмка, отгрузка,
  перемещение), касса (проведённый чек теперь списывает остаток). Строка остатка без ячейки — одна на товар и склад
  (дубли, если были, слиты при выкладке).

### Стоимость (value)

- **Приход** — стоимость из учёта (себестоимость поступления без НДС, ровно дебет счёта запасов документа); если
  автопилот документ не отражает — сумма строки документа (основание «по документу»). Поэтому при проведении сначала
  отражение в учёте, затем движения.
- **Расход, перемещение, возврат покупателя** — стоимость определяет себестоимость (FIFO/средняя, FP-031): в отчёте
  она берётся из записей себестоимости документа по товару и складу и распределяется по строкам пропорционально
  количеству (остаток округления — последней строке). Снятое с проведения стоимость не «выдумывает».
- Стоимость видна только с правом бухгалтерских отчётов; кладовщик (`stock.read`) видит количества.

### Приёмка поступления

- В строке поступления: **по документу** (накладная поставщика / заказ), **принято** (идёт в остаток и учёт),
  **отказ** (брак, пересорт — не принят), **причина** (недостача, излишек, брак, пересорт, другое) и пояснение.
  Недостача = по документу − принято − отказ, излишек — наоборот.
- Проверки: расхождение — только с причиной, причина — по существу (недостача только при недостаче, брак/пересорт —
  при отказе, «другое» — с пояснением); без расхождения причина не нужна; поля приёмки — только у поступления;
  принято 0 — только если товар ожидался (строка без проводок и движений); ничего не принято во всём документе — нельзя.
- **Частичная приёмка по заказу:** «создать на основании» заказа подставляет остаток заказа как «по документу»;
  исполнение заказа считает **принятое**, недостача и отказ остаются к поставке. Заказ показывает исполнение по
  строкам (заказано / принято / осталось), отказ, поставку сверх заказа и документы-поступления.
- Сумма претензии поставщику = (недостача + отказ) × цена строки; излишек — отдельно.
- Поля приёмки входят в хэш версии документа (изменение причины — новая версия, отменяет согласование FP-029);
  у документов без них хэш прежний.

### API и экраны

- `GET accounting/stock-movements` (фильтры: товар, склад, период, вид, документ; остаток на начало для карточки),
  `GET accounting/stock-movements/check` (сверка остатка с журналом), `GET accounting/receipt-discrepancies`
  — право `stock.read`, суммы — с `acc.reports.read`.
- Торговый документ: вкладка «Движения склада», у поступления — режим «Приёмка с расхождениями» (колонки «по
  документу / принято / отказ / причина», подсветка недостачи/излишка, пояснение), предупреждение с суммой
  претензии; у заказа — вкладка «Исполнение».
- «Торговля → Движения товаров»: журнал (документ, строка, версия, вид, количество, стоимость и её основание,
  встречные/отменённые), кнопка «Сверить остаток с журналом», вкладка «Расхождения приёмки».

## Не сделано / ограничения

- Ячейки хранения (`bin_id`) журнал поддерживает, но документы пока пишут без ячейки — адресное хранение в FP-032.
- Стоимость расхода в журнале не хранится, а берётся из себестоимости при чтении (себестоимость пересчитывается
  задним числом; хранить её копию — значит держать вторую правду). Итог стоимости за период по фильтру — нет (только
  количества); стоимостная оборотка — отчёт «Остатки и себестоимость» по учёту.
- Закрыть остаток заказа («больше не ждём») — нет: заказ остаётся частично исполненным; закрытие и возврат
  поставщику по расхождению — FP-035.
- Расхождения не порождают документ претензии/акта и не меняют расчёты с поставщиком: в учёт и долг идёт принятое
  количество; претензия — сумма в отчёте.
- Старые модули (касса, «Закупки») передают количество числами JavaScript — точность как была (не хуже прежней).
- Удаление тестовых данных клиента требует режима обслуживания (тестовые помощники `test/stock-helpers.ts`).
- Попутно замечено, не исправлялось: витрина аналитики (`analytics-worker`, `mart.service.ts`) читает таблицу `stocks`,
  которой нет (таблица — `stock`) — снимок остатков витрины не строится; отдельная задача.
