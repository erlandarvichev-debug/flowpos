  (≥ 32 символов; заглушка из примера настроек = выключено), через nginx закрыт; метки — только id организаций.
  Плюс очередь outbox по статусам, истёкшие аренды outbox и «давность последнего прохода» фоновой обработки.
- **Оповещения** (`esf-alerts.ts`, чистые правила): ESF_UNKNOWN, ESF_SENDING_STUCK, ESF_SYNC_FAILING, ESF_SYNC_STALE,
  ESF_NO_SESSION, ESF_QUARANTINE, ESF_SIGNING_FAILURES, ESF_REJECTED, ESF_DECISIONS_OVERDUE — у каждого важность,
  **ответственный** (бухгалтер / ответственный за решения / дежурный инженер) и раздел runbook. Таблица `ops_alerts`:
  одно открытое на ключ (уникальность в БД через `open_key`, без частичного индекса — `db push` его бы снёс);
  повтор той же важности — не чаще 6 ч / 1 ч, рост важности — сразу, закрытие — отдельным событием; журнал
  `OPS_ALERT_RAISED/RESOLVED`. Доставка: строка лога и вебхук `OPS_ALERT_WEBHOOK_URL` (без секретов). Оценка — в
  каждом фоновом проходе по организации. На экране ЭСФ — плашка открытых оповещений; в «Настройках» —
  «Состояние обмена с ИС ЭСФ».
- **Внешний сторож:** `deploy/monitoring/flowpos-esf.rules.yml` — API недоступен, фоновая обработка встала (этого
  внутренние оповещения сами не увидят), зависшие отправки, UNKNOWN > суток, outbox.
- **Трассировка:** код запроса из `X-Request-Id` (веб присылает свой на каждое действие; небезопасный заменяется
  новым) или новый; возвращается в ответе; фоновый проход — `esf-tick-<uuid>`. Код идёт в `set_config` вместе с
  клиентом (FP-009), и `audit_log.trace_id` заполняется **значением по умолчанию в БД** — во всех записях журнала,
  включая транзакции, без правки каждого вызова. Он же — в строках лога (`[trace …]`), в вызовах шлюза ИС ЭСФ
  (`[ESF-GW]` операция/среда/исход/длительность, без тел) и в `ops_alerts`. В сообщении об ошибке пользователь видит
  «Код обращения».
- **Маскирование секретов:** `common/redact.ts` + глобальный `RedactingLogger` (сообщение, контекст, стек): PEM,
  XMLDSig, JWT, Bearer, пароль в адресе, `sessionId`/подпись/сертификат/тикет/токен в JSON, XML и `ключ=значение`,
  переменные `*_SECRET/PASSWORD/TOKEN/KEY`, длинный base64. Коды ошибок (`ESF_SIGNATURE_INVALID`) не трогаются.
  Ошибки синхронизации и тексты оповещений сохраняются уже замаскированными.
- **Карантин входящих (временный, до FP-024):** неразобранный входящий — запись `ESF_INBOUND_UNPARSED` с телом как
  получено (до 1 МБ), SHA-256, рег. номером и причиной; метрика и оповещение; из счётчика уходит, когда ЭСФ с этим
  идентификатором появится в реестре.
- Отказ проверки подписи — `ESF_SIGNING_REJECTED` (код, без подписи и сертификата); запись — лучшая попытка: её сбой
  не подменяет ошибку пользователю (найдено полным прогоном: тестовый `userId` без пользователя ронял FK журнала).
- Новый вход в ИС ЭСФ обнуляет счёт сбоев; при закрытой сессии вместо «синхронизация падает» — «нет входа».
- Runbook: `docs/erp/runbooks/ESF.md` — где смотреть, ответственные, действия по каждому оповещению и правилу.
