# Печатные формы, конструктор печати и акт сверки

**Status:** ⚠️ DONE_LOCAL — акт сверки взаиморасчётов (экран + печать); печатные формы З-2, Р-1, КО-1, КО-2 по
приказу МФ РК № 562, счёт на оплату, акт сверки; конструктор шаблонов (поля документа, живой предпросмотр на реальном
документе, версии, «по умолчанию», архив), реквизиты для подписей; кнопка «Печать» в торговых и кассовых документах;
проверено визуально (локально); не выкладывалось
**Date:** 2026-11-02

## Источники форм

- **Приказ МФ РК от 20.12.2012 № 562** «Об утверждении форм первичных учётных документов» (рег. № 8265, действует;
  текст с изменениями на 28.03.2018 — zakon.uchet.kz V1200008265): З-2 — прил. 26 (ред. № 402), Р-1 — прил. 50
  (ред. № 458), КО-1 — прил. 1, КО-2 — прил. 2. Надписи и колонки — дословно по бланку.
- Проект изменений 2026 года (Конституция 2026: «теңге», «Индивидуальный идентификационный номер/…», «Место печати»,
  legalacts id 15836845) — принятие **не подтверждено**; при принятии поправить шаблоны в конструкторе.
- Счёт на оплату и акт сверки — утверждённой формы нет (ст. 7 п. 3 Закона «О бухучёте» — обязательные реквизиты),
  по деловой практике; в счёте — образец платёжного поручения (ИИК, БИК, Кбе, КНП 710).

## Как устроено

- **Шаблон** — HTML с подстановками собственного движка (`print/engine.ts`, общий для API и веба, без зависимостей):
  `{{поле}}`, форматы `|money |date |qty |words` (сумма прописью «… тенге NN тиын») `|upper |lower |default:`,
  `{{#each lines}}…{{/each}}` с `{{@n}}`, `{{#if}}…{{else}}…{{/if}}`. **Код из шаблона не выполняется.** При
  сохранении отклоняются script/iframe/object/embed/base/link/meta/form, обработчики on*, javascript:, внешние ресурсы.
  Отрисовка — в изолированной рамке (sandbox без скриптов + CSP: никаких загрузок). Печать и PDF — средствами браузера.
- **Шаблоны организации** `print_templates`: каждое сохранение — новая версия (текст версии неизменен, `sql/160`),
  одна версия по умолчанию на вид, архив вместо удаления; встроенные — в коде, «по умолчанию», пока не выбран свой.
- **Данные для печати** (`print/print.service.ts`): организация (реквизиты, банк, Кбе 17/19, руководитель, бухгалтер,
  кассир из «Реквизиты и подписи»), контрагент (адрес, банк), строки с НДС тем же расчётом, что проводки и ЭСФ;
  накладная — только товары, акт Р-1 — только услуги; ордера — счета проводки (дебет / корр. счёт), «от кого / кому»;
  поставщик/покупатель по направлению документа; количество и сумма прописью.
- **Акт сверки** (`reports/reconciliation.ts`): сальдо на начало, строки по документам (дебет — долг контрагента
  растёт, кредит — уменьшается), обороты, сальдо на конец; счета расчётов из учётной политики (1210/3510/3310/1710);
  договор — по желанию. Печать — в две стороны («по данным организации» / «по данным контрагента»).
- **Экраны:** «Администрирование → Печатные формы» (конструктор + «Реквизиты и подписи»), «Отчёты → Акт сверки»,
  кнопка «Печать» в реализации, поступлении, заказах, возвратах, ПКО/РКО.

## Проверка

  поля для конструктора. Интеграционные `print.int-spec.ts` (4): версии, «по умолчанию», архив, неизменность в БД,
  чужая организация; данные реализации (НДС 16%, прописью, стороны, товары/услуги), все встроенные шаблоны проходят
  проверку и отрисовываются (З-2: количество «три», сумма прописью; Р-1 — дата работ), ПКО (счета 1010 / 3510 после
  проведения), акт сверки (аванс покупателя → долг в его пользу). `reconciliation.int-spec.ts` (1): 1000 + 500 − 600
  − 100 = 800, поставщик −1000, чужой контрагент.
- Все наборы: unit 153/153, интеграционные 277 (+1 пропуск), стенд ЭСФ 230/230, сборка веба.
- **Визуально:** счёт на оплату по реализации (прописью «Пятьсот тенге 00 тиын», НДС 68,97), конструктор (поля,
  редактор, предпросмотр), З-2 по бланку.

## Не сделано / ограничения

- Надписи «тенге/теңге», «ИИН/БИН», «М.П.» — как в действующей редакции; переключателя нет (правятся в шаблоне).
- PDF формируется браузером («Печать → Сохранить как PDF»), не сервером; пакетной печати нет.
- Конструктор — редактор разметки с полями и предпросмотром, не визуальный «перетаскиватель».
- Нет форм: доверенность, счёт-фактура на бумаге, ТТН, инвентаризационная опись, авансовый отчёт, кадровые формы.
- Р-1: колонка «Сведения об отчёте…» и «Сведения об использовании запасов заказчика» не заполняются автоматически.
