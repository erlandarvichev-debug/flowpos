# FP-036: Банк, касса, авансы и разнесение

**Status:** ⚠️ DONE_LOCAL — ключ строки выписки на счёте (номер операции банка или содержимое + номер повтора в файле),
повторная/параллельная загрузка не зачисляет дважды, оборванная загрузка дозачисляется; оплаты (банк и касса, покупатель
и поставщик) гасят долг **по документам расчётов** — автоматически от самого старого или вручную, остаток — аванс;
неизменяемый журнал разнесений с отменой «кто, когда, почему» и аудитом; экран разнесения проверен визуально (локально);
не выкладывалось
**Date:** 2026-11-02
**Backlog:** Treasury · P1 · deps FP-028, FP-026 · acceptance: *Bank key scoped by account; дубли не зачисляют дважды; allocation/reversal audited*

## Было

- Ключ строки выписки — хэш содержимого: две одинаковые оплаты одного покупателя за день (та же сумма, назначение)
  считались дублем — вторая терялась. Номер операции банка не использовался.
- Две загрузки одной выписки одновременно могли создать два документа по строке; загрузка, оборвавшаяся после записи
  строки, но до документа, при повторе строку пропускала — оплата не зачислялась никогда.
- Оплата гасила долг контрагента «вообще» (сальдо 1210/3310), без привязки к документам: по какой реализации долг
  закрыт — неизвестно, выбрать документ нельзя, истории разнесения нет.

## Стало

- **Ключ строки выписки** (на банковский счёт организации): есть колонка «Референс» (номер операции банка) — ключ по
  ней; нет — содержимое строки + какая по счёту такая же строка в файле (`#2`, `#3`): две одинаковые оплаты — две
  строки, повторная загрузка того же файла — те же ключи, ничего нового. Тот же файл на другой счёт — свои ключи.
  В строке хранятся `reference` и `occurrence`.
- **Параллельная / оборванная загрузка:** строка и документ уникальны в БД; вторая загрузка получает уже созданные
  (а не ошибку), «уже проведён» считается проведённым. Строка без документа (обрыв) при повторе дозачисляется
  (`resumed` в итоге).
- **Разнесение оплат** (BANK_IN/OUT, CASH_IN/OUT с покупателем/поставщиком): долг гасится проводками с аналитикой
  «документ расчётов» (`SETTLEMENT_DOC`).
  - Автоматически — от самого старого по дате первой проводки (долг без документа — старые проводки — по своей дате);
    остаток — аванс.
  - Вручную — `body.allocations: [{ docId, amount }]`: только открытые документы этого контрагента, сумма > 0, не больше
    долга по документу, документ — один раз, всего — не больше оплаты (`ALLOC_*`); остаток — аванс.
  - Отчёт «открытые позиции» `GET accounting/open-items?counterpartyId&side=IN|OUT&date&excludeDocId`.
- **Журнал разнесений** `payment_allocations`: после проведения, изменения проведённого, снятия и пометки на удаление
  платежа действующие строки сверяются с проводками; изменилось — прежние отменяются (`REVERSED`, кто, когда, причина),
  пишутся новые; каждое изменение — в аудите (`PAYMENT_ALLOCATED` / `PAYMENT_ALLOCATION_REVERSED`). БД (`sql/130`)
  запрещает менять строку иначе как отменой с причиной и удалять (кроме обслуживания ролью миграций).
  `GET accounting/documents/:id/allocations` — история.
- **Документ с разнесёнными оплатами** (реализация, поступление…) нельзя снять с проведения или изменить, пока оплата
  на нём: `PAYMENTS_ALLOCATED` (409) — сначала перенести оплату на другой документ или снять её.
- **Экран платежа:** «Разнесение» — автоматически / вручную; таблица открытых документов контрагента с долгом и суммой,
  «в аванс уйдёт»; вкладка «Разнесение» — действующие и отменённые строки с причиной.

## Проверка

- Интеграционные `treasury.int-spec.ts` (4): две одинаковые оплаты → 2 строки, повторная загрузка → 0, номер операции —
  ключ (одинаковое содержимое с разными номерами — две строки, тот же номер в новой выписке — дубль), другой счёт — свои строки; две загрузки одновременно → по одному
  документу на строку; оборванная загрузка дозачисляется; авто-разнесение долгов 1000 и 500: оплата 1200 → 1000 на
  старую + 200 на новую, оплата 500 → 300 на новую + 200 аванс, журнал и аудит; ручное — все проверки `ALLOC_*`, 250 на вторую + 50 аванс, изменение с
  причиной → прежние строки отменены (автор, время, причина), снятие проведения → журнал пуст; `PAYMENTS_ALLOCATED` у
  документа с оплатой и снятие документа без оплаты; БД не даёт изменить сумму, удалить, отменить без причины.

- Все наборы: unit 163/163, интеграционные 275 (+1 пропуск; в одном из четырёх прогонов 1 нестабильный сбой, не
  повторился), стенд ЭСФ 230/230, сборка веба.
- **Визуальная проверка** (локально, «ТОО «Демо ЭСФ»», счёт «Демо: Kaspi Bank»): поступление 300 вручную → 200 на

## Не сделано / ограничения

- Разнесение — на документы, по которым долг возник после FP-036 (с `SETTLEMENT_DOC`); старый долг виден одной строкой
  «без документа» и гасится по дате своей первой проводки (обычно первым).
- Зачёт аванса против новой реализации отдельным документом (взаимозачёт) — нет; аванс остаётся на 3510/1710.
- Разнесение по договорам/валютам — в пределах аналитик проводок; курсовые разницы — FP-042.
- Банк-клиент (выгрузка платёжек), платёжный календарь и заявки — FP-037.
- Сопоставление строки выписки с документом по назначению платежа (номер счёта в тексте) — нет; разнесение
  загруженных из выписки оплат — автоматическое (можно переразнести вручную изменением платежа).
