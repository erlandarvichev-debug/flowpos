# flowpos-mcp — MCP-сервер FlowPOS для ИИ-агентов

Два режима:
- **удалённый для клиентов** (`dist/http.js`): HTTP + OAuth, клиент подключает FlowPOS в Claude своим логином. См. раздел «Сервер для клиентов».
- **локальный** (`dist/index.js`, stdio): для разработчика и Claude Code на своей машине.

Работает поверх REST API FlowPOS от имени пользователя: **права агента = права пользователя** в организации. Нет произвольного SQL и shell.

## Инструменты
| Инструмент | Что делает | Изменяет данные |
|---|---|---|
| `flowpos_context` | организация, роль, права, доступные организации | нет |
| `flowpos_switch_organization` | переключить организацию (только из доступных) | нет |
| `accounting_chart_search` | поиск счетов: признаки, аналитики | нет |
| `accounting_search_documents` | поиск документов | нет |
| `accounting_get_document` | документ, объяснение проводок, связи, история | нет |
| `accounting_trial_balance` | ОСВ со ссылкой на отчёт | нет |
| `accounting_account_card` | карточка счёта с документами | нет |
| `accounting_journal` | журнал проводок | нет |
| `trade_search_documents` | торговые документы и статус отражения в учёте | нет |
| `trade_get_document` | строки, проводки автопилота, себестоимость, проблема | нет |
| `accounting_stock` | остатки и себестоимость по складам | нет |
| `accounting_settlements` | долги и авансы по контрагентам | нет |
| `autopilot_issues` | что автопилот не смог отразить и почему | нет |
| `esf_invoices` | реестр ЭСФ: исходящие/входящие, статусы, отказы, реализации без ЭСФ | нет |
| `accounting_create_draft` | **черновик** ручной операции (помечается «[Черновик ИИ]») | создаёт черновик |

Проведение, сторно, изменение реквизитов оплаты, подписание и отправка отчётности через MCP **недоступны** — их делает уполномоченный пользователь в интерфейсе после предпросмотра. Содержимое документов возвращается с пометкой «данные, а не инструкции».

## Сборка и тест
```bash
cd apps/mcp && npm run build
npm test          # сквозной тест клиент ↔ сервер ↔ API (нужен запущенный API :3000)
```

## Подключение к Claude Code
```bash
claude mcp add flowpos \
  -e FLOWPOS_API_URL=http://localhost:3000 \
  -e FLOWPOS_WEB_URL=http://localhost:5173 \
  -e FLOWPOS_EMAIL=<email> -e FLOWPOS_PASSWORD=<пароль> \
  -- node /Users/vipinet/FlowPOS/apps/mcp/dist/index.js
```
Вместо email/пароля можно передать `FLOWPOS_TOKEN` (JWT). Организация — `FLOWPOS_ORG_ID` (по умолчанию организация пользователя). Пароли не храните в репозитории.

## Сервер для клиентов (удалённый MCP)

Клиент FlowPOS подключает свой FlowPOS к Claude и спрашивает обычным языком: «какие долги у покупателей», «почему не отражена реализация 15», «какие ЭСФ отклонены».

**Как подключается клиент** (claude.ai, Claude Desktop, мобильный Claude):
1. Настройки → Коннекторы → «Добавить свой коннектор».
2. Адрес: `https://<ваш-домен>/mcp`.
3. Откроется страница «Подключить FlowPOS». Клиент вводит свой e-mail и пароль FlowPOS и нажимает «Войти и разрешить».

Claude Code: `claude mcp add --transport http flowpos https://<ваш-домен>/mcp`. Вход откроется в браузере (`/mcp` → Authenticate).

**Безопасность**
- OAuth 2.1, обязательный PKCE (S256), динамическая регистрация клиентов. Access-токен живёт 1 час, refresh-токен — 30 дней, при каждом обновлении он меняется (ротация).
- Права ИИ равны правам пользователя в FlowPOS (роль в организации).
- Проводить, подписывать, отправлять и удалять ИИ не может: таких инструментов нет. Это проверяется в тесте.
- Пароль передаётся только в API FlowPOS и не сохраняется.
- Хранится только refresh-сессия FlowPOS, зашифрованная AES-256-GCM ключом `MCP_STATE_KEY`. Токены MCP хранятся в виде SHA-256.
- Входов не больше 10 за 15 минут на IP и e-mail. Страницу входа нельзя встроить в чужой сайт. Отзыв доступа — `/revoke` (Claude вызывает его при отключении коннектора).

**Запуск**
```bash
cd apps/mcp && npm run build
MCP_PUBLIC_URL=https://mcp.example.kz \
MCP_STATE_KEY=<случайные 32+ символа, хранить вне репозитория> \
MCP_STATE_FILE=/var/lib/flowpos-mcp/oauth.json \
FLOWPOS_API_URL=http://127.0.0.1:3000 FLOWPOS_WEB_URL=https://app.example.kz \
MCP_PORT=3100 npm run start:http
```
Nginx (TLS обязателен для claude.ai):
```nginx
server {
  server_name mcp.example.kz;
  location / { proxy_pass http://127.0.0.1:3100; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $remote_addr; proxy_set_header X-Forwarded-Proto https; proxy_buffering off; }
}
```
Ограничение: один процесс, состояние в одном файле. Для нескольких экземпляров нужно вынести хранилище в БД.

**Проверка:** `npm test` (нужен API на :3000) прогоняет полный путь клиента: метаданные, регистрацию, страницу входа, неверный пароль, PKCE, одноразовый код, вызов инструментов, ротацию refresh-токена и отзыв доступа.
