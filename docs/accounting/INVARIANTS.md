# Бухгалтерские инварианты

| # | Инвариант | Где обеспечено | Проверка (тест) |
|---|---|---|---|
| I1 | Дебет = Кредит в каждой записи по каждому разрезу (BU/NU) | `PostingService.validate` + deferred constraint trigger `acc_postings_balance_trg` | «БД сама запрещает несбалансированную запись» |
| I2 | Суммы только Decimal/NUMERIC, ≤2 знаков; количество ≤3 | `money()` + `NUMERIC(18,2/3)` | «отклоняет … 10.001» |
| I3 | Документ проводится атомарно | одна транзакция Prisma на проведение | все тесты проведения |
| I4 | Повтор запроса не создаёт дублей | заголовок `Idempotency-Key` (`idempotency_records`) + повторное проведение той же версии возвращает существующую запись + частичный уникальный индекс «одна ACTIVE-запись на источник» | «повторное проведение не создаёт дублей» |
| I5 | Параллельные операции не ломают учёт | `SELECT … FOR UPDATE` документа, атомарная нумерация `INSERT … ON CONFLICT … RETURNING`, advisory-lock периода | «параллельные проведения», «уникальные номера» |
| I6 | Проведённое нельзя изменить незаметно | триггер `acc_postings_immutable_trg` (UPDATE/DELETE запрещены), изменение проведённого документа — только с причиной, версия +1, перепроведение в той же транзакции | «изменение проведённого документа требует причину» |
| I7 | Исправления сохраняют историю и связь с исходным | `acc_document_versions` (неизменяемы, триггер), старая запись `SUPERSEDED`, сторно = новый документ с `reversalOfId` | «сторно обнуляет обороты» |
| I8 | Закрытый период не меняется без права и аудита | `PeriodsService.assertOpen` (право `acc.period.override` + причина → `audit_log`) | «закрытый период нельзя изменить» |
| I9 | Каждый показатель расшифровывается до проводки и документа | ОСВ → `drill` → карточка счёта → `source.link` документа | ручная проверка UI + API |
| I10 | Изоляция организаций | `OrgGuard`, фильтр `organization_id`, проверка ссылок `REF_FOREIGN` | «документы другой организации недоступны» |
| I12 | Отрицательные остатки запрещены (если политика не разрешает) | `CostService` в транзакции проведения + advisory-lock по товару | тесты NEGATIVE_STOCK, конкурентные списания |
| I13 | Себестоимость воспроизводима: повторный пересчёт не меняет учёт | детерминированный порядок, версия = хэш проводок | тест «повторный пересчёт ничего не меняет» |
| I14 | Складские движения неизменяемы | триггер `acc_stock_moves_immutable_trg` | — |
| I15 | Выписка не загружается дважды | уникальный хэш строки на счёт | тест выписки |
| I11 | У проводки — ссылка на документ и версию правила | `acc_entries.source_type/source_id/source_version/rule_code/rule_version` | журнал проводок |
| I16 | Закрытие месяца воспроизводимо: повторное закрытие без изменений учёта даёт те же итоги и проводки | детерминированные проводки закрытия (`PERIOD_CLOSE`, версия = хэш), снимок итогов в `acc_period_closes` | тест «повторное закрытие» |
| I17 | Закрывающие проводки не искажают ОПиУ | проводки финрезультата с `rule_code = FIN_RESULT` исключаются из отчёта | тест ОПиУ за год после закрытия |
| I18 | Баланс сходится | проверка Актив = Пассив в каждом отчёте (незакрытый результат — в строке 414) | тесты баланса |
| I19 | Нельзя закрыть месяц с блокирующими проблемами | мастер проверяет до записи; исключительная advisory-блокировка на время закрытия | тест «блокирующие проблемы» |

## Правила (спроектированы; реализация по этапам)
- **Округление:** половина вверх от нуля до 2 знаков (`round()`); налоги — по правилу, указанному в налоговых параметрах года (этап 4). Разница округления распределения относится на последнюю строку.
- **Курсовые разницы (этап 2–3):** сумма в тенге = валюта × курс НБРК на дату операции / кратность, округление по правилу выше; переоценка монетарных статей на дату закрытия месяца документом «Переоценка» (6250/7430).
- **Себестоимость (этап 3):** метод из учётной политики на дату (FIFO / средняя). Документ задним числом помечает период «требует пересчёта себестоимости» с этой даты; пересчёт — регламентной операцией закрытия, повторный запуск даёт тот же результат.
- **Документы задним числом:** допускаются только в открытом периоде; в закрытом — сторно текущей датой либо переопределение по праву с аудитом.
- **Отрицательные остатки (этап 2):** запрещены по умолчанию; разрешение — флаг учётной политики с предупреждением и обязательным пересчётом.
