# FlowPOS ⇄ vp-net.kz: API лицензирования — В ПРОДЕ, МОЖНО ПОДКЛЮЧАТЬ

Обновлено 2026-09-16 по спеке разработчика РМК (`FLOWPOS_SERVER_SPEC.md`).
Сервер vp-net.kz реализует контракт кассы **1:1**. **Задеплоено на прод
https://vp-net.kz, все проверочные тесты из спеки прогнаны на бою — зелёные**
(включая реальную доставку /api/support в Telegram). Касса может подключаться
прямо сейчас; не хватает только файла установщика (п. latest.json).

## Контракт кассы (по спеке, реализовано 1:1)

### POST /api/license/check — лицензия по логину МойСклад

Вход: `{ "login": "shop@example" }` (регистронезависимо).
Ответы (application/json, 200):
- лицензирован: `{ "licensed": true, "demo": false, "expiresAt": "2027-01-01"|null, "note": "..." }`
- нет: `{ "licensed": false, "demo": true, "reason": "not-licensed" }`
- истёк: `{ "licensed": false, "demo": true, "reason": "expired", "expiresAt": "..." }`
- пустой логин: `{ "licensed": false, "demo": true, "reason": "no-login" }`

`licensed:true` только если логин в списке, active и срок не истёк.
Хранилище — PostgreSQL сайта (таблица `ms_licenses`), управление — из CRM.

### POST /api/support — сообщение из кассы → Telegram

Вход: `{ "message": "...", "from": "...", "login": "...", "version": "..." }`.
Ответы: `200 {"ok":true}` · `400 {"ok":false,"error":"empty"}` ·
`503 {"ok":false,"error":"telegram-not-configured"}` · `502 telegram-failed`.
Токен: env `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` приоритетнее; если не заданы —
берётся бот, настроенный в админке сайта (Настройки → Telegram).

### GET /flowpos/latest.json — версия последнего релиза

`{ "version": "0.1.40", "url": "https://vp-net.kz/flowpos/FlowPOS_0.1.40_x64-setup.exe", "notes": "" }`

Если в папке раздачи лежит ручной `latest.json` — отдаётся он. Иначе ответ
**генерируется автоматически** из самого свежего (по mtime) `.exe` в папке,
версия парсится из имени файла (`x.y.z`). Нет файлов → `404 {"error":"no-release"}`.

### GET /flowpos/<installer>.msi|.exe — установщик статикой

Поддерживаются **.msi** и .exe (у РМК установщик msi): имя
`FlowPOS_x.y.z_x64-setup.msi`, версия берётся из имени, latest.json укажет на него.

Папка раздачи на сервере: `/opt/vpnet/server/data/downloads/` (в репо —
`server/data/downloads/`). **Процесс релиза: разработчик присылает
`FlowPOS_x.y.z_x64-setup.exe` → кладём в папку → всё.** Кассы сами увидят
новую версию, рестарт сервера не нужен.

## Отличия от спеки (согласованные адаптации)

1. **`GET /` не трогаем** — на корне живёт сайт vp-net.kz. Страница скачивания:
   `https://vp-net.kz/products/flowpos` (промо + кнопка) и `https://vp-net.kz/account`
   (кабинет клиента). Тесты спеки корень не проверяют.
2. **Админка** — не `?pass=`, а существующая CRM: `https://vp-net.kz/admin` →
   вкладка **«Лицензии» → «Касса: логины МойСклад»**: добавить/продлить
   (+30д/+год), выключить/включить, удалить, примечание. Вход по аккаунту
   менеджера (JWT), HTTPS.
3. **Сервер** — прод vp-net.kz это 31.169.16.29 (ssh -p 1985), не 31.169.160.7.
4. HTTPS уже есть (nginx перед Node), ответы `/api/*` — application/json.

## Дополнительно доступно (сверх спеки, можно игнорировать)

- `POST /api/license/request` `{name, phone|email, company?, login?, deviceId?, message?}` —
  «Запросить лицензию» из кассы: заявка падает лидом в CRM + Telegram/WhatsApp
  уведомление менеджеру. Ответ `{ok:true, message:"..."}`.
  ✅ Доработка из контракта 0.1.42 сделана: при наличии `login` создаётся
  «ожидающая» запись в Лицензии→Касса (active=false, в примечании имя/телефон/
  компания) — менеджер активирует одним переключателем «Включить».
  Существующая запись повторной заявкой не сбивается.
- Вход в кассу с логином без лицензии → владельцу мгновенно летит Telegram
  со ссылками «активировать в 1 клик» (30 дней / год / бессрочно), дедуп —
  раз в сутки на логин.
- Кабинет клиента на сайте (`/account`): регистрация, trial-ключи
  `FPOS-XXXX-XXXX-XXXX`, скачивание дистрибутива — параллельный контур,
  кассе он не нужен.
- Легаси-контракт `check` по ключу: если в теле есть `key` и нет `login`,
  `/api/license/check` работает по старой схеме key+deviceId.
