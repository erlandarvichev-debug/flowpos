# FP-031: Себестоимость и дополнительные расходы

**Status:** ⚠️ DONE_LOCAL — доп. расходы (доставка, таможня…) в стоимость товаров поступления с детерминированным распределением; доля уже проданного — в себестоимость; стоимость следует за перемещённой партией; метод оценки — метод периода; эталон «себестоимость 2200 / прибыль 800 / остаток 8800» обоими методами; экран проверен визуально (локально); не выкладывалось
**Date:** 2026-11-02
**Backlog:** Inventory · P1 · deps FP-030 · acceptance: *Fixture COGS2200 profit800 stock8800; остаток округления детерминирован; метод периода*

## Было

- Доставка/таможня в поступлении (услуга) уходила в расходы периода (7020) — себестоимость товара занижена, прибыль
  от продажи завышена. Отдельного документа «доп. расходы» не было.
- Метод оценки брался по дате движения: версия учётной политики с середины месяца смешивала FIFO и среднюю внутри
  месяца; сменить метод можно было задним числом, в том числе в закрытом периоде (пересчёт переоценил бы закрытые месяцы).
- Партии FIFO не помнили, из какого поступления они: перемещение склеивало куски в одну безымянную партию.

## Стало

- **Документ «Доп. расходы на поступление»** (`LANDED_COST`, номер `ДР-…`): на основании проведённого поступления
  своей организации, не раньше его даты; поставщик услуги, строки услуг, НДС к зачёту; распределение **по сумме строк
  (без НДС)** или **по количеству**. Проводки: Дт 1330 (по товарам и складу поступления, количество 0 — растёт только
  стоимость) / Кт 3310, НДС Дт 1420. Остаток (количество) не меняется — движений журнала FP-030 нет.
- **Округление детерминировано:** доли до тиына, остаток округления целиком — строке с наибольшим весом (при равенстве —
  с меньшим номером); сумма долей всегда равна сумме расходов; повторный пересчёт не создаёт новых записей.
- **Себестоимость (CostService):**
  - партии помнят строку поступления; при перемещении куски партий переезжают со ссылкой;
  - доп. расходы на дату документа: на ещё не списанное количество строки — в стоимость партий (на любом складе;
    часть на другом складе — перенос стоимости Дт 1330 склад / Кт 1330 склад поступления), на уже списанное — в
    себестоимость продаж (Дт 7010 / Кт 1330) на дату доп. расходов;
  - средняя: идентичность партий потеряна — в стоимость остатка склада поступления доля min(остаток, количество
    строки) / количество строки, остальное — в себестоимость;
  - средняя: последняя единица забирает весь остаток стоимости (без «зависших» тиынов).
- **Метод периода:** метод берётся из политики, действующей на 1-е число месяца движения (версия с середины месяца
  действует со следующего месяца). Смена метода — только с 1-го числа (`METHOD_PERIOD_START`) и только в открытом периоде
  (`METHOD_PERIOD_CLOSED`); другие поля политики — с любой даты.
- **Зависимости:** проведённое поступление с проведёнными доп. расходами нельзя изменить, снять с проведения или пометить
  на удаление (`LANDED_COST_DEPENDS`, 409) — сначала доп. расходы.
- **Экран:** у проведённого поступления «Ещё → Доп. расходы (доставка, таможня…)»; документ показывает основание,
  базу распределения, проводки по товарам. Попутно исправлено: режим «приёмка с расхождениями» переносился в новый
  документ другого типа при переходе из поступления — колонки сдвигались, цена попадала в количество (найдено на
  визуальной проверке).

## Проверка

- Модульные `landed-cost.spec.ts` (3): пропорции, остаток округления (равные веса, порядок, мелкие суммы, сумма сходится,
  повторяемость), нулевая/отрицательная база.
- Интеграционные `cost-landed.int-spec.ts` (11): **эталон FIFO и средняя** — 10 × 1000 + доставка 1000, продажа
  2 × 1500 → 7010 = 2200, 6010 = 3000, прибыль 800, 1330 = 8800, долг поставщикам 11000, повторный пересчёт без
  изменений; доп. расходы **после продажи** (200 в себестоимость на их дату, итог тот же, затем продажа остатка → 11000 и
  0) обоими методами; перемещённая партия (6600 / 4400 по складам, продажа со второго склада 4400); по сумме и по
  количеству, НДС к зачёту, округление 33.34/33.33/33.33; средняя без копеек; проверки основания (нет, черновик, не
  поступление, раньше даты, неизвестная база — и для черновика, и при проведении), зависимость поступления (снять,
  пометить, изменить — 409; после снятия доп. расходов — можно); пробное проведение; метод периода (смена с середины
  месяца, закрытый период; политика с 15.10 действует с ноября: октябрь FIFO 10, ноябрь средняя 30).
- **Мутации — 17/18 пойманы, 1 эквивалентная:** остаток округления, кому остаток, доля проданного, «всё в остаток»,
  ссылка партии при перемещении, перенос стоимости между складами, средняя мимо остатка, метод по дате движения, смена
  метода с середины месяца / в закрытом периоде, база распределения, НДС в стоимость, зависимость поступления, проверки
  основания (проведено, дата, база), склад из основания. Первый прогон: 3 не компилировались (переформулированы), 2
  выжили — проверка сохранения дублировалась проверкой проведения; добавлен тест черновика. **M8 (средняя: весь остаток
  по округлённой средней) — эквивалентная:** точности Decimal (20 знаков) хватает, чтобы round(c / q × q) = c; явная
  ветка оставлена для ясности.
- Все наборы: unit 163/163, интеграционные 248 (+1 пропуск), стенд ЭСФ 230/230.
- **Визуальная проверка** (локально, «ТОО «Демо ЭСФ»»): поступление → «Ещё → Доп. расходы» → основание и база в шапке →
  доставка 116 ₸ с НДС → проведено: 1420 16,00; 1330 71,43 + 28,57 (по сумме строк 300/120); 3310 116,00 → снять
  поступление — «К поступлению … проведены доп. расходы ДР-…».

## Не сделано / ограничения

- Доля уже списанного товара идёт в 7010 (себестоимость продаж) независимо от того, как товар выбыл (продажа, списание,
  возврат поставщику) — для списаний и возвратов точнее был бы их счёт; отдельная доработка.
- Доп. расходы по нескольким поступлениям сразу (одна накладная перевозчика на несколько поступлений) — нет, по одному
  основанию; таможня/импорт с валютой и ТН ВЭД — FP-047.
- Стоимость движения прихода в журнале FP-030 — исходная (без доп. расходов); стоимость с доп. расходами — в учёте и
  в стоимости расхода.
- Средняя — скользящая (по каждому движению), не средневзвешенная за месяц.
- Смена метода внутри уже открытого месяца проверяется только при записи политики; политика, записанная раньше с
  середины месяца, действует со следующего месяца (без ошибки).
