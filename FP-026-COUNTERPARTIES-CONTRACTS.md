# FP-026: Контрагенты, договоры и реквизиты

**Status:** ⚠️ DONE_LOCAL — реквизиты с проверкой (ИИН/БИН, IBAN, БИК, КБе), адреса и счета с датами действия, договор принадлежит организации и проверяется везде, где на него ссылаются; экраны проверены визуально (локально); не выкладывалось
**Date:** 2026-11-01
**Backlog:** Catalog · P1 · deps FP-025, FP-008 · acceptance: *Effective dates; адреса/БИН; доступ; нет чужих ссылок*

## Было

- **Договор без организации.** Договор заключает организация, а в модели он висел на контрагенте клиента: документ
  организации A мог сослаться на договор организации B (проверялась только видимость контрагента); список договоров
  бухгалтерии (`GET accounting/contracts`) отдавал договоры **всех организаций клиента**; карточка контрагента —
  тоже. Бухгалтерские торговые документы договор не проверяли вовсе; срок действия договора не проверялся нигде.
- **Адресов и банковских счетов у контрагента не было** — в ЭСФ адрес покупателя не уходил. ИИН/БИН — любые 12
  цифр, дубли контрагентов по БИН не замечались.
- API контрагентов принимал **любые поля** (`msId`, `onecGuid`, `syncStatus`, `deleted`, `owner`).
- **Экран:** форма слала поле `address`, которого нет в модели, — создание контрагента падало; «ИНН» вместо ИИН/БИН.
- ЭСФ: «Дата договора» бралась из начала действия, а не из даты договора.

## Стало

- **Реквизиты** (`catalog/requisites.ts`, чистые функции): ИИН/БИН — 12 цифр с контрольным разрядом РК (два прохода
  весов; проверено на реальных БИН); IBAN — модуль 97, для KZ 20 символов; БИК; КБе (резидентство + сектор). Вид
  контрагента: юрлицо / ИП / физлицо / нерезидент (у нерезидента своя страна и налоговый номер без проверки формата).
  Дубль БИН у видимого контрагента — 409 с именем; у личного контрагента другой организации — без имени.
  Смена БИН — в журнал. Белый список полей.
- **Даты действия:** адреса (юридический / фактический / доставки) и банковские счета с `validFrom`/`validTo`.
  Новый адрес того же вида закрывает прежний днём раньше; начать раньше уже действующего нельзя (прошлое не
  переписывается). Счёт закрывается датой; основной — один на валюту. `GET counterparties/:id/requisites?on=` —
  адрес и счёт на дату.
- **Договор принадлежит организации** (`contracts.organization_id`, составной FK — той же клиентской области),
  номер уникален в паре «организация — контрагент», дата договора обязательна, срок действия, вид, валюта, признак
  «действует». Договоры другой организации клиента не видны ни в карточке, ни в справочнике бухгалтерии.
- **Нет чужих ссылок** — договор проверяется везде, где на него ссылаются:
  торговые документы (`assertTradeRefs`: своя организация, тот же контрагент, действует, в сроке на дату документа);
  бухгалтерские торговые документы (`validateRefs`); проводки (`checkDimOwnership`: своя организация, контрагент
  строки, срок на дату записи); ЭСФ (договор читается только своей организации).
  Изменение договора, по которому есть документы: нельзя сменить валюту и сузить срок так, чтобы документы вышли за
  него.
- **ЭСФ:** адрес покупателя — юридический, действующий на дату оборота; «Дата договора» — дата договора.
- **Экраны:** список контрагентов (вид, «личный», ИИН/БИН, переход в карточку), форма в полях API; карточка —
  реквизиты, «Реквизиты на дату», история адресов и счетов, договоры организации (создание, изменение, закрытие).
- **Выкладка без `--accept-data-loss`:** `sql/pre/070_fp026_contract_org.sql` заполняет организацию существующих
  договоров однозначно (личный контрагент → документы с договором одной организации → единственная организация
  клиента); неоднозначные и дубли номеров — остановка с перечнем. Новые таблицы — в триггерах заполнения клиента
  (FP-007) и под RLS клиента (FP-009).

## Не сделано / ограничения

- «Основной» счёт не хранит историю: если на дату действовали несколько счетов, выбирается помеченный основным, иначе
  открытый позже.
- Обмен с 1С/МойСклад реквизиты (адреса, счета, договоры) пока не переносит — только наименование и БИН, как раньше.
- Проверка государственных реестров (статус БИН в КГД, плательщик НДС) — нет.
- Наименование контрагента не версионируется (переименование видно в журнале изменений записи, а не на дату).
- Договоры, созданные до FP-026 без даты, в ЭСФ дают дату начала действия (если есть).
